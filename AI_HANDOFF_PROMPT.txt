68) LATEST IMPLEMENTED UPDATE (OFFLINE SYNC MULTI-PASS: CREATE→PAY ORDERING)
==================================================
- Request:
  - Offline paid tickets still not uploading when back online.
- Root cause:
  - Offline queue can contain `pay` tasks that reference a negative mock order ID.
  - If sync tries to run `pay` before the matching `create` establishes a mock→real ID mapping,
    the pay hits `/pay` with a negative ID and fails; then the `create` may succeed later, but the

    - always prioritizes `create/submit` before `update` before `pay`
    - defers `update/pay` tasks until a mock→real mapping exists
    - retries pending tasks up to 3 passes in the same sync call
  - Added sync debug logs (`[OFFLINE SYNC] ...`) to make failures visible.
